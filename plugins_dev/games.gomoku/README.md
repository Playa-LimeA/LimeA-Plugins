# 五子棋插件

与当前聊天角色一起下五子棋。角色通过当前会话的模型选择落子，插件负责棋盘、规则校验、胜负与存档。可选择模型独立思考或本地引擎辅助；最终落子始终由模型决定。插件不读取模型密钥，也不自行发送模型请求。

当前正式版本为 **0.3.2**，需要支持插件接口版本 **12** 的 LimeA。插件详情页提供玩法说明和对局设置，不包含账号连接。

## 安装与游玩

本版本需要支持插件接口版本 12 的 LimeA。从插件市场安装并启用，或在「设置 → 插件 → 导入插件」选择本插件构建出的 `dist` 目录。旧宿主请先更新，不要直接安装此版本。也可以从插件管理的详情页查看玩法说明。

切到 Chat（聊天模式），在右侧「小游戏」打开「五子棋」，点击「开始对局」。也可以在聊天中邀请角色下棋，由模型调用工具打开棋盘。普通回复运行期间不能另开对局。沿用当前会话的角色、模型与思考强度。

- 15×15 自由五子棋，无禁手；每局随机分配黑白，黑棋先行。
- 双方轮流落子，横、竖或斜向连续五颗及以上同色棋子获胜；满盘且无人获胜则和棋。
- 点击交点落子；方向键移动选择，回车落子。最近一手标记圆点，获胜连线高亮。
- 双方每次确认落子播放短音效；右上角「声音开 / 声音关」可切换并记住偏好。恢复棋局和重复同步不会重播，面板隐藏后暂停声音。浏览器尚未获得用户交互授权时可能暂不出声，点击棋盘或声音按钮后即可启用。
- 用户可以认输；提前「结束游戏」不会给未完成的本局计分。
- 仅在用户回合可认输或结束；模型思考和局末回应期间禁用这些操作，后台同样校验。结果确定后仍立即显示两个选项；「下次再玩」等待角色回应并进入等待续局状态后开放，暂停的棋局也可直接结束。
- 一局结束，棋盘上方立即显示结果和「再来一局 / 下次再玩」，无需向下滚动。角色用一句话回应结果；提前选择续局会先保存选择，回应后开局。连续对局累积比分；结束后重新开始是一场新的比赛。
- 停止运行、模型失败或重启时保留棋盘，点击「继续对局」恢复。同步失败时禁止操作，重新读取已保存状态，不自动补下棋子。

规则是用于陪玩的自由规则变体，不包含竞技禁手或交换开局。[Gomocup 规则说明](https://gomocup.org/detail-information/)区分了自由五子棋与其他规则。

## 对局设置

在「设置 → 插件 → 五子棋」打开插件详情页，在「对局设置」区调整，无需新建聊天或先开始游戏。游戏右上角的「对局设置」仍然可用，两处入口复用同一份表单、后台命令和数据库，提供：

- **模型落子**（默认）：只向模型提供棋盘，由它自己分析。
- **引擎辅助**：使用本地 `@algorithm.ts/gomoku` 4.0.5，计算最多三个候选落点和评估分，再交给模型选择。模型也可选择其他合法空点。
- **普通 / 困难**：普通分析两步、候选较少；困难分析四步、候选更多。等级影响分析深度，不能保证模型棋力或胜率。

设置保存在插件数据库，所有聊天共用，从下一局开始生效；恢复暂停棋局仍使用该局原设置。引擎在独立线程内运行，不访问网络。单次预算为 2.5 秒，超时使用已完成的较浅分析，没有分析结果时回退到模型自行判断。当前局面分析复用到该回合结束，取消运行或停用插件时终止计算。

评分为从角色执子视角的启发式评估分，越高越好，**不是胜率**。上游搜索把某些强威胁标为无穷值，适配层将其表示为 ±900000000；这不等于已经取胜。当前落子直接成五才标记为 `winning-line`、1000000000。提示将分析作为角色可用的局面计算，角色自然回应并自行决策，不要求播报分数或虚构推理过程。

仅复用库的局面评估和搜索器，插件负责候选排序、评分转换、线程生命周期与限时适配，不另造搜索算法。开源引擎及其队列依赖随安装包分发，许可证见 [THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt)。

## 模型如何读取棋盘

列为 `A…O`，从左到右；行为 `1…15`，从上到下。每次轮到模型，宿主持续交互接口提供完整、最新的文字棋盘：`X` 是黑棋，`O` 是白棋，`.` 是空点，同时明确角色与用户各自的颜色、符号和已有落点，以及轮次、上一手、当前局编号和状态版本。`model` 始终代表角色自己，`human` 始终代表用户（对手），与黑白颜色无关；续局重新读取当局分配，不沿用上一局颜色。工具结果、结算和历史也说明这组身份。模型不需要从截图识别棋子，也不依靠旧聊天记住落子历史。

工具：

- `start`：开始、恢复对局，或在局末等待用户决定是否续局。
- `place_stone`：例如 `{ "roundId": "来自最新状态", "revision": 12, "row": 8, "column": "H" }`。
- `history`：查询当前聊天最近五局的完整落子顺序、颜色、结果和比分；不打开游戏，不开始新局。

后台验证会话与运行归属、当前局与版本、轮次、坐标和空位。对局中工具结果返回简短状态，完整棋盘由宿主每步提供；结算结果另带完整顺序棋谱，结束游戏时附最近五局摘要，因此后续普通聊天仍能读取对局信息。历史不够明确时，模型可调用 `history` 查询持久记录。模型连续漏调用工具时，宿主补一次指定工具请求，仍未调用则暂停；已调用工具但参数或执行失败时，宿主反馈错误并继续请求模型纠正，用户可停止运行。非法落子不修改状态，后续请求仍提供最新棋盘。用户思考时工具保持等待，不产生模型请求。胜负以后台结果为准。

## 数据与权限

插件标识为 `games.gomoku`，只声明 `fs:plugin-data`。启用即信任插件代码，权限声明不构成系统沙箱。

通过宿主托管数据库保存到 `storage/plugin-data/games.gomoku/databases/matches.sqlite`；第一条迁移为 `1000_initial`。每段会话保存当前比赛的棋子、黑白归属、回合、比分与已执行操作标识。与鲨鱼等插件数据库独立，不占主程序迁移编号。升级保留数据；旧操作不能重复落子或计分。

`1001_settings_history` 新增设置与对局存档，不修改既有迁移。每局结算或主动结束时，在同一事务中更新当前状态并归档；未完成的棋局标为未完成，不计输赢。续局、开始新比赛和重启不会覆盖历史，查询按聊天隔离。升级能补存旧版本仍保留的最后一局，已经被旧版本续局覆盖的更早棋谱无法恢复。`recordedAt` 是归档时间，补存的旧棋局不冒充原始结束时间。

本插件的回合等待与恢复流程复用鲨鱼插件的现有实现并适配五子棋；运行时没有跨插件依赖，不要求安装鲨鱼。

0.3.1 将对局设置移入插件详情页，安装卡片不再单独提供设置弹窗；游戏内「对局设置」和详情页复用同一份设置表单。

## 开发与验证

需要 Node.js（JavaScript 运行时）24 或以上。在本目录执行：

```sh
npm ci
npm test
npm run build
```

只在构建阶段使用 esbuild（打包工具）和 Sharp（图片处理库）；安装包不携带开发依赖。图标由仓库内的棋盘矢量图生成 192×192 PNG（便携式网络图形）图片。

桌面集成测试复用本机 LimeA 的 Playwright（浏览器自动化库）、Electron（桌面运行框架）与模拟模型协议夹具。先构建宿主，再设置以下路径；测试使用临时用户目录和本地模拟服务，不调用付费模型：

```powershell
$env:LIMEA_REPO_DIR = '你的 LimeA 源码目录'
$env:LIMEA_TEST_APP_DIR = '包含 package.json 的已构建 LimeA 目录'
npm run test:desktop
```

`npm test` 验证规则、非法与过时操作、取消恢复、事务失败、历史隔离、设置持久化，以及引擎候选合法性、直接成五、防守、超时和取消。桌面测试验证实际安装、完整棋盘传递、重试、声音、续局、退出、重启、设置弹窗和真实请求中的历史棋谱；模拟模型故意选择第二候选，核对最终落子遵循模型选择。截图和运行记录位于被忽略的 `artifacts/`。

在仓库根目录打包并更新市场清单：

```sh
npm run pack:plugin -- plugins_dev/games.gomoku/dist entries/games.gomoku.json
npm run check -- --allow-stale
```
