# 0.1.1 出卷流程设计

状态：独立设计及代码复审通过，已实现并完成隔离桌面验证。用户已批准本流程，要求评审后实现并发布。

## 目标与复用

改为定结构、固定模板、逐题生成、整卷审核、开放作答。正常 N 题只发起 N+2 次插件私有模型请求；宿主内部的结构纠正不计入此数。不再逐题独立解答与二次审校。复用现有托管数据库、私有模型任务、短事务、取消与回执、Zod 校验、KaTeX 和原生表单，不新增依赖、不改宿主权限或公共接口、不改冻结迁移。

## 数据、题型与模板

- `spec` 增加可选 `questionTypes: [{type,count}]`，支持 single/multiple/judge/fill/short。不能重复，数量合计必须等于总题数；未传由蓝图决定。面板可选自动或手动题型数量，主聊也可明确指定。
- 蓝图仍只有一次模型请求，冻结每题题型、考点、分值、用时；验证 100 分、总题数、题型数量、时间上限。新蓝图按单选、多选、判断、填空、解答顺序分节，题号连续。版式固定为插件模板，不另发排版请求。
- 单选唯一答案；多选至少两个正确选项，全部匹配才得分。判断固定 T=正确/F=错误，仅选一个。程序为这三类覆盖生成的评分规则，禁止要求过程分。
- 填空题有 1–4 个 `blanks: [{id, answers, points}]`，编号 b1 起，题干中每个 `[[bN]]` 必须恰好出现一次；每空 1–6 个允许答案，分值合计等于该题。空格独立输入，答案按顺序保存为字符串数组。仅 NFC（标准组合规范化）与首尾去空格的精确匹配直接给分，保留上标、下标、大小写等数学语义；未匹配的非空答案一次交模型按语义逐空判定 correct/incorrect/uncertain，返回的空号集合必须恰好等于待判集合，不得覆盖精确命中或空答，由程序按每空固定分数相加，不把可能等价表达直接判错。空答零分，任一不确定则整题待复核、总分不确定。
- 解答题沿用文本输入与冻结评分标准。每题内容仍限 2200 字符（含 blanks），保持整卷预算。旧已就绪/作答/提交试卷冻结不动。

## 审核投影与输出

新增纯函数从同一份持久结构化试卷生成 Markdown 审核视图，包括计划、每题题干、选项、答案、评分规则、解析。它不是第二份数据，不解析回写。审核调用直接嵌入原始文档，避免重复传整卷 JSON 或二次转义；修订元数据单独序列化。完整提示总长校验 <=58000；文档不用 HTML 或执行能力。

审核输出为 `issues: [{questionIds, severity, category, reason}]`，最多 20 项，severity 为 blocking/advice，category 为 answer/conditions/type/duplicate/leakage/scope/workload/style/balance/uncertainty。每项必须定位到真实题号，reason<=500 字符。没有 blocking 即通过；style/balance 只能是 advice，uncertainty 强制为 blocking。其余类别既可建议也可阻断；提示词明确阻断真实答案错误、无法求解或判分、重复考题/泄题、明确超范围、明显无法按时完成，以及无法可靠核验答案/条件的情况。模型必须重新计算/核对答案，不能仅接受给定答案。

原始审核理由可能含答案，只存私有库。公开工具与面板仅显示程序映射的类别、题号、数量和阶段；不得公开模型 reason、文档、答案键或填空允许答案。建议不导致额外模型调用。

## 状态、取消、返工与兼容

`papers.data` 增加可选 generation 对象，version=2；使用 stage=draft/review/repair/verify/blocked，修订目标与每题尝试计数随状态持久化，无数据库迁移。

1. 蓝图保存后逐题生成；每题只作结构校验，保存后再下一题。格式错误最多一次自动重试，耗尽暂停，显式继续可重置这道题的格式重试计数。已完成题不会重发。
2. 首次整卷审核没有阻断就 ready。发现阻断时保存问题和目标题号，进入 repair，保留原题作为修改依据，每个目标修订后持久移出待修订集合。
3. 所有目标修订后，仅一次 verify 请求：文档包含整卷供交叉检查，但指令聚焦原问题、改动题和它们对其他题的影响。未改题保持原样。修订仍有阻断则 stage=blocked 并暂停，不自动再循环。
4. stage 与待修订集合先于请求持久化。取消/断线/重启不会重置返工预算、重发已经完成的题或跳过最终复核。迟到结果仍经现有 operationId 校验丢弃。明确点击继续才允许 blocked 状态进入新一轮有界修订；重复 executionId 不产生新一轮。
5. 旧版暂停试卷在用户继续时惰性接入新流程：保留能通过新结构校验的已生成题与候选（客观题评分规则规范化），无效项重新生成；清理旧 solve/audit 工作缓存，旧请求日志保留。旧审核结论不能直接发布，必须走一次新整卷审核。旧 ready 试卷完全不变。

## 界面与边界

准备页显示固定模板与题型分配、已生成 N/M、整卷审核/修订复核阶段，避免“已审核全部但仍暂停”的误解。暂停显示具体题号与安全问题类别；继续的含义明确为继续剩余步骤或再尝试一轮修订。考前仍不展示题目，考试开始才计时。作答页按题型分节，填空保存、中文组字、焦点、卸载恢复复用现有机制。交卷前不开放参考答案与解析。

## 验证与发布

- 后台：正常 5 题严格 7 次请求；建议不阻断、不确定强制阻断；真错误仅修改指定题；修订一次失败暂停；取消/重启横跨 repair/verify 不重复工作；旧暂停接入、旧 ready 冻结；格式重试有界；恶意/无效题号拒绝；所有公开投影无答案泄漏；20 题最大中文预算，含 verify 的原问题反馈及完整转义后提示。复核原问题采用类别/题号及有界理由摘要，最多额外 4000 序列化字符；逐题修订可读取原完整理由。
- 新题型：明确数量约束；判断单选；多选至少两个；填空编号/分数/空答/规范化精确命中/等价表达/部分得分/不确定/越界结果；x²、x₂ 不得与 x2 精确匹配；持续覆盖原计时、保存、回执和跨会话隔离测试。
- 隔离真实桌面：五题型结构→生成→一次审核→开考→填空输入保存/卸载恢复→交卷批改；窄面板、公式与原有竞争回归。使用模拟模型验证调用次数与行为，真实模型耗时不作固定秒数承诺。
- 插件升版 0.1.1，构建、测试、格式检查、市场校验，独立代码复核后按任务分支→dev→main 发布；保留 0.1.0 分发文件以兼容缓存，核对在线目录与安装包摘要、镜像同步。

## 独立设计评审记录

首轮结论：需修改。指出兼容规范化会抹去数学上、下标区别，以及缺少无法可靠核验时的明确阻断。已改为 NFC 与首尾去空格，增加 uncertainty 强制阻断类别，并补足相关反例、未知空号集合和复核请求预算。独立复审结论：通过；没有扩大宿主接口或权限边界。

## 实施与验证（2026-11-15）

独立代码审查指出：最大范围包含大量反斜杠时，将整份 Markdown 再序列化会导致复核提示超限，继续也无法恢复。已改为直接嵌入原始文档，补充转义范围反例。独立复审结论：通过；原案例首次审核 50,721 字符、复核 54,668 字符，均低于上限，文档内容保持原样。

- 后台 29 项测试通过，覆盖五题七请求、建议/不确定分类、定向修订与持久阶段、旧卷兼容、五题型判分、答案隔离、最大完整提示以及原计时/保存/回执回归。
